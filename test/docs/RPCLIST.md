# MultiChain RPC command reference

Every RPC command this node registers, taken from the call table in
[`src/rpc/rpclist.cpp`](../src/rpc/rpclist.cpp) and from the help strings in
[`src/rpc/rpchelp.cpp`](../src/rpc/rpchelp.cpp) (plus the inline help of the
wPoA and WeightEngine commands, which lives in the two handler files
[`src/rpc/rpcwpoa.cpp`](../src/rpc/rpcwpoa.cpp) and
[`src/rpc/rpcweightengine.cpp`](../src/rpc/rpcweightengine.cpp)).

296 commands are registered across 12 categories.

## How to read the flag columns

The three booleans are the last three fields of each `CRPCCommand` entry. They are
read by `CRPCTable::execute()` in [`src/rpc/rpcserver.cpp`](../src/rpc/rpcserver.cpp).

| Column | `true` (✅) | `false` (—) |
| --- | --- | --- |
| **okSafeMode** | The command still runs while the node is in *safe mode* — i.e. while `GetWarnings("rpc")` reports an active warning, such as a detected fork or an alert. | The call is rejected with `RPC_FORBIDDEN_BY_SAFE_MODE` for as long as the warning stands, unless the node was started with `-disablesafemode`. Reserved for commands that move money or change state, so a node that may be on a bad chain refuses them. |
| **threadSafe** | The actor runs straight on the RPC worker thread, taking **no** global lock. Used by commands that touch only their own structures or already lock internally, so they stay responsive while a block is being processed. |  The actor runs under `LOCK2(cs_main, pwalletMain->cs_wallet)` (or `cs_main` alone when there is no wallet). Serialised against block validation and wallet updates. |
| **reqWallet** | The command needs the wallet. Without one it is reported as `Method not found (disabled)`; in practice the flag now selects the commands that take the wallet read lock. | No wallet needed. |

Two further gates are set elsewhere, in `mc_InitRPCHelpMap()`, and are noted inline
in the tables below when they apply:

- **available with `-offline`** — listed in `setAllowedWhenOffline`, so it still answers on a node started offline.
- **available while waiting for a protocol upgrade** — listed in `setAllowedWhenWaitingForUpgrade`, so it answers even when the chain has moved to a protocol version this build does not support.

Parameters are transcribed from each command's own help text; long argument
descriptions are abridged, so `multichain-cli <chain> help <command>` remains the
authoritative source for the full argument and result schemas.
